# SmartOil Roadmap

Живой статус продукта. Обновляется после каждого значимого изменения, аудита или принятого архитектурного решения.

## Текущий релиз: стабилизация эксплуатационного контура

### Цель

Сделать единообразной и проверяемой цепочку:

`MaintenanceEvent -> EquipmentUnit.current_* -> OilLifecycle -> MaintenanceSchedule -> dashboards`

### В работе

- Приёмка desktop/mobile логики замены и долива масла.
- Приёмка пересборки OilLifecycle после изменения событий ТО.
- Проверка plan-fact замены масла на реальных сценариях.
- Поддержка ответственного за несколько активов.
- Единая ролевая фильтрация дашбордов.
- Безопасное разделение франчайзинговых ролей: `client_admin` и `lab_technician`.

### Следующий релиз

- Уведомления о критических анализах, просроченном ТО и приближении отбора проб.
- Расширенная аналитика OilLifecycle.
- Автоматический пересчёт SamplingSchedule после создания новой пробы.

## Направление: AI Investigation Platform

Отдельный продукт в том же репозитории. Полный план — `src/docs/investigation/mvp-plan.md`.

### Завершено

- Architecture Decision Record, entity model и permissions model.
- Решение о собственном стеке вместо Base44 (`adr-0002-own-stack.md`).
- Схема PostgreSQL 16 + pgvector на 29 таблиц, генерируемая из одного определения.
- Изоляция арендаторов через row-level security базы, роль приложения без `bypassrls`;
  неизменяемость журналов обеспечена триггерами. Проверено на работающей базе.
- Слоистая архитектура: UI → Services → Engine → Agents → Repositories → PostgreSQL;
  замена хранилища не потребовала правок в методологии.
- Аутентификация сотрудников, сессии, HTTP-контур дела и контур участника интервью.
- Развёртывание на VPS: Docker, Caddy, GitHub Actions с прогоном всех проверок до выкладки.
- Замкнут цикл расследования §67: 11 агентов из 18, аналитический цикл, второй раунд.
- Исполнитель фоновых задач в контейнере API: очередь в той же базе, остановка на
  утверждении человеком.
- Резервное копирование с обязательной проверкой копии восстановлением.
- Скрипт перевода доступа к серверу на ключи с откатом при любом сбое.
- Экран участника интервью: самодостаточная страница по подписанной ссылке.
- Итоговый отчёт: классификация выводов, утверждение человеком, версии, выпуск.
- Абстракции `GraphRepository`, `KnowledgeStore`, `FileRepository`, `AuditRepository`.
- Подсистема источников: SHA-256, неизменяемый оригинал, derived Source, Source → Evidence.
- Agent Framework: контракт агента, защита от prompt injection, валидация JSON-схемы, `AgentRun`.
- Пять агентов: Case Manager, Intake Analyst, Investigation Planner, Claim Extractor, Red Team.
- Машина стадий и методологические инварианты в коде.
- Демонстрационное дело Missing Cash 001 и приёмочный прогон §81: 33/33.

### В работе

- Развёртывание на сервере: поддомен, секреты, первый прогон Action (`KI-013`).
- Укрепление доступа: ключи владельца и запуск готового Action (`KI-018`).
- Приём голосовых ответов и вложений от участника (`KI-025`).
- Внешнее хранилище резервных копий (`KI-019`).

### Следующий релиз направления

- Follow-Up Planner и второй раунд интервью.
- Final Reviewer и Report Writer.
- Экраны: Case Dashboard, Timeline, Evidence Matrix, Contradiction Map, Hypothesis Board.
- Telegram-бот интервью.
- Голосовые ответы участников: whisper.cpp на сервере, транскрипция задачей очереди.
- Разбор документов как задача очереди.
- Построение эмбеддингов для поиска похожих дел и утверждений.

## Завершённые вехи

- Архитектура моточасов на базе MaintenanceEvent.
- Удаление SamplingPoint: один агрегат является единственным местом отбора.
- Привязка проб, графиков отбора, lifecycle и QR непосредственно к EquipmentUnit.
- Безопасное сохранение форм через buildPayload и useSaveMutation.
- Пороговые правила масла и индивидуальные пороги агрегата.
- Приём входящих проб в собственной и клиентской таре, вложения фотографий.
- Сравнение проб: рейтинги, диаграммы, автошкала и печать/PDF.
- Дашборд флота корректно различает отсутствие анализа и анализ без рассчитанного OHI.
- Полукруглые индикаторы корректно отображают широкие и вложенные пороговые диапазоны.
- Настроен и документирован резервный канал живых проверок Base44 через CLI + Deno.
- Добавлен инкрементальный старт сессии через `PROJECT_STATE.md` и Git checkpoint.
- Лабораторный ввод анализа выделен в scoped-роль `lab_technician`; `/mobile-lab` поддерживает ручное создание входящей пробы без QR.

## Правило обновления

После каждого принятого этапа:

1. Перенести завершённые пункты в «Завершённые вехи».
2. Обновить риски и следующий шаг.
3. Зафиксировать проверенную практику или тупиковый путь в `src/docs/engineering-practices.md`.
4. Выполнить build/lint и создать отдельный понятный commit.
