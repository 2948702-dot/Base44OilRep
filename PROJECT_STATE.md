# SmartOil: текущее состояние

Короткая точка входа для продолжения работы. Полная документация читается только по необходимости.

## Текущий фокус

- Релиз: стабилизация эксплуатационного контура.
- Следующий приоритет: `KI-001` / P0 — RLS и поддержка полного массива `User.asset_ids`.
- После него: `KI-002` и `KI-003` — acceptance для MaintenanceEvent, OilLifecycle и plan-fact замены масла.

## Последнее подтверждённое состояние

- Ветка `main` синхронизирована с GitHub.
- Документационный аудит слит PR #1.
- Build и lint проходят.
- Typecheck не проходит из-за накопленного baseline, см. `KI-011`.
- Живой read-only доступ Base44 работает через CLI + Deno.
- Последний production snapshot: 6 активов, 7 агрегатов, 6 проб, 9 результатов анализа.
- SamplingPoint удалён из рабочей модели; legacy-записи production требуют отдельной проверки перед удалением.
- В модели ролей добавлены scoped-роли франчайзи: `client_admin` и `lab_technician`; `client_admin` включает права лаборанта и мобильного оператора, чтобы франчайзи мог стартовать в одном лице.
- Для входящей пробы без QR `/mobile-lab` должен давать ручной выбор клиента, актива/агрегата или базового масла.

## Инкрементальный старт

1. Найти checkpoint — последний коммит, изменивший этот файл:

   `git log -1 --format=%H -- PROJECT_STATE.md`

2. Посмотреть, что изменилось после checkpoint:

   `git diff --name-status <checkpoint>..HEAD`

3. Если список пуст, прочитать только этот файл и приступить к текущему P0.
4. Если изменения есть, сначала прочитать diff и только документы/модули затронутой области.
5. Полностью читать `ROADMAP.md`, `known-issues.md`, архитектуру и бизнес-правила только при:
   - изменении соответствующего файла;
   - смене продуктового приоритета;
   - противоречии между состоянием, кодом и production;
   - подготовке архитектурного решения или релиза.

## Правило обновления

Обновлять этот файл при изменении:

- текущего приоритета или статуса P0;
- подтверждённого production-состояния;
- незавершённых проверок;
- ключевой архитектуры или источника истины.

Не превращать файл в журнал действий. История остаётся в Git, решения — в `decisions.md`, риски — в `known-issues.md`.
