# BOBR status bot

Телеграм-бот, который сидит в рабочем чате с подрядчиком BOBR AI, ведёт реестр
договорённостей и уведомляет нашу команду, когда статус договорённости меняется.

Подрядчик подключение нашего бота в свой чат согласовал (переписка с Ариной
Игнатьевой, 28.07.2026: на вопрос «Можем туда подключить нашего чат-бота — он будет
фиксировать договорённости, смотреть за ходом выполнения, накапливать базу знаний?»
ответ «Да»).

## Что делает

1. Читает все сообщения в группе «645 ID | BOBR».
2. Раз в N минут отдаёт накопленные сообщения Claude, который вытаскивает из них
   договорённости: что обещано, кто ответственный, к какому сроку.
3. Ведёт реестр со статусами: `promised` (обещано) → `in_progress` (в работе) →
   `done` (сделано), плюс `overdue` (просрочено) и `cancelled` (отменено).
4. На каждую новую договорённость и на каждую смену статуса шлёт уведомление
   в наш внутренний чат — в чат подрядчика по умолчанию ничего не пишет.
5. Сам переводит договорённость в `overdue`, когда срок прошёл, а отметки о
   выполнении нет.
6. Раз в день присылает сводку по всем открытым договорённостям.

Всё состояние — в одном JSON-файле, база не нужна.

## Что нужно от вас перед запуском

1. **Создать бота.** `@BotFather` → `/newbot` → имя и username. Токен из ответа
   вставьте в `.env`, в чат его не пересылайте.
2. **Выключить privacy mode.** `@BotFather` → `/mybots` → ваш бот → *Bot Settings*
   → *Group Privacy* → **Turn off**. Без этого бот видит в группе только команды,
   а не переписку, и отслеживать будет нечего.
3. **Добавить бота в группу** «645 ID | BOBR» и дать права администратора
   (или хотя бы убедиться, что privacy mode выключён до добавления).
4. **Узнать id чатов.** Отправьте `/chatid` в группе BOBR и в нашем внутреннем
   чате — бот ответит числами для `BOBR_CHAT_ID` и `TEAM_CHAT_ID`.
5. **Узнать свой user id** — `@userinfobot`, значение `Id` → в `ADMIN_USER_IDS`.

Бот не видит сообщения, отправленные до того, как его добавили в группу, — это
ограничение Telegram. Историю до этого момента закрывает стартовый реестр (см. ниже).

## Установка

```bash
cd bots/bobr-status-bot
npm install
cp .env.example .env   # заполнить токены и id
npm run seed           # разово: реестр из истории переписки с Ариной
npm start
```

`npm run seed` загружает `seed.json` — 13 договорённостей, собранных вручную из
переписки за 23.07–16.08.2026 (тестовый бот, план внедрения, ЮKassa, оплата тарифа
и прочее). Если реестр уже не пуст, посев пропускается; перезаписать — `npm run seed -- --force`.

Тесты:

```bash
npm test
```

## Команды

| Команда | Что делает |
|---|---|
| `/agreements` | открытые договорённости |
| `/agreements all` | весь реестр, включая закрытые |
| `/card <id>` | карточка с историей статусов |
| `/status <id> <статус> [комментарий]` | сменить статус вручную |
| `/new Текст \| ГГГГ-ММ-ДД \| bobr` | завести договорённость руками |
| `/digest` | сводка прямо сейчас |
| `/analyze` | разобрать накопленные сообщения немедленно |
| `/pause`, `/resume` | приостановить и возобновить разбор |
| `/chatid`, `/whoami` | id чата и ваш id |

Статусы принимаются и по-русски: `сделано`, `в работе`, `отмена`, `просрочка`.

Команды, кроме `/chatid`, `/whoami` и `/help`, доступны только id из `ADMIN_USER_IDS`.

## Настройка

Все параметры — в `.env` (см. `.env.example`). Что стоит знать:

- `NOTIFY_IN_SOURCE_CHAT=false` — по умолчанию бот не пишет в чат подрядчика.
  Поставьте `true`, только если решите, что уведомления полезны обеим сторонам.
- `ANALYZE_INTERVAL_SEC` и `ANALYZE_MIN_BATCH` — компромисс между скоростью
  реакции и расходом токенов. Разбор запускается по таймеру или когда накопилось
  `ANALYZE_MIN_BATCH` сообщений.
- `ANTHROPIC_EFFORT=medium` — глубина рассуждений модели. Для более аккуратного
  распознавания поднимите до `high`, для экономии опустите до `low`.
- `src/project-context.js` — контекст проекта (участники, интеграции, план внедрения),
  который целиком уходит в системный промпт. Держите его в актуальном состоянии:
  он сильнее всего влияет на качество распознавания.

## Как это устроено

```
Telegram getUpdates ──▶ буфер сообщений ──▶ Claude (structured output)
                                                 │
                              новые договорённости│ смены статуса
                                                 ▼
                                          реестр (state.json)
                                                 │
                               уведомления ──────┴────── ежедневная сводка
```

- `src/telegram.js` — клиент Bot API на long polling, без вебхуков и белого IP.
- `src/analyzer.js` — вызов Claude с JSON-схемой ответа: модель не может вернуть
  произвольный текст, только валидный разбор.
- `src/agreements.js` — реестр и машина статусов: запрещённые переходы
  (например, `cancelled` → `done`) отклоняются.
- `src/index.js` — цикл опроса, применение разбора, просрочки, сводка.

Записи с уверенностью модели ниже 0.6 отбрасываются, дубли по нормализованному
тексту не заводятся. Если разбор упал — сообщения остаются в очереди и попадут
в следующий заход, ничего не теряется.

## Развёртывание

`deploy/bobr-status-bot.service` — юнит systemd. Разложить в `/opt/bobr-status-bot`,
`chmod 600 .env`, дальше:

```bash
sudo systemctl enable --now bobr-status-bot
journalctl -u bobr-status-bot -f
```

Запускать один экземпляр: два процесса с одним токеном конфликтуют на `getUpdates`
(в логе будет 409).

## Вынести в отдельный репозиторий

Папка самодостаточна — внешних зависимостей от SmartOil нет:

```bash
cp -r bots/bobr-status-bot /path/to/bobr-status-bot
cd /path/to/bobr-status-bot && git init && git add . && git commit -m "init"
```

## Ограничения

- Разбор чата вероятностный: модель может пропустить договорённость или
  завести лишнюю. Реестр правится руками — `/status` и `/new`.
- Голосовые сообщения не расшифровываются: в разбор идёт только текст и подписи
  к файлам. В чате с BOBR голосовых много, часть договорённостей будет мимо.
- Прямой интеграции с BOBR нет: API они открывают только на тарифе «Стандарт»,
  документация доступна в их личном кабинете (`dashboard.bobr-service.ru/guide`).
  Если тариф оплатят и API дадут — источник событий можно будет заменить,
  разбор чата останется как страховка.
