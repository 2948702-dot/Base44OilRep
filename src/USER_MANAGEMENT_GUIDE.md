# Алгоритм управления пользователями и RBAC

## Архитектура ролей (Role-Based Access Control)

### Три основные роли:

1. **Администратор (`admin`)**
   - Полный доступ к управлению системой
   - Может добавлять новых пользователей (всех ролей)
   - Может просматривать и управлять всеми клиентами
   - Может управлять справочниками (масла, пороги, и т.д.)
   - **Главная страница**: Dashboard с глобальной статистикой по всем клиентам

2. **Суперинтендант (`superintendent`)**
   - Видит все суда флота и их состояние
   - Может просматривать данные по пробам масла и обслуживанию
   - Видит критические суда первым
   - Может анализировать тренды по всем активам
   - **Главная страница**: FleetDashboard с обзором мониторинга флота

3. **Капитан (`captain`)**
   - Доступ только к СВОЕМУ назначенному судну
   - Может видеть детали оборудования своего судна
   - Может просматривать историю анализов
   - **Главная страница**: Автоматический редирект на страницу своего судна

## Процесс приглашения и добавления пользователя

### Шаг 1: Администратор открывает "Управление пользователями"
- Переходит на страницу `/users`
- Видит таблицу всех существующих пользователей с их ролями

### Шаг 2: Администратор нажимает "Пригласить пользователя"
- Открывается диалог с полями:
  - **Email** (обязательное поле)
  - **Роль** (выпадающий список: Администратор, Суперинтендант, Капитан)
  - **Назначить судно** (появляется только если выбрана роль "Капитан")

### Шаг 3: Выбор роли и параметров
- **Если выбран "Суперинтендант"**: отправляется приглашение с этой ролью
- **Если выбран "Капитан"**: требуется обязательно выбрать судно (asset)
  - Выпадающий список показывает все доступные судна (assets)
  - Капитан будет автоматически привязан к этому судну

### Шаг 4: Отправка приглашения
- Система вызывает `base44.users.inviteUser(email, role)`
- Пользователь получает приглашение на указанный email
- Ссылка приглашения действительна определенный период времени

### Шаг 5: Пользователь принимает приглашение
- Переходит по ссылке из email
- Регистрируется в системе
- Его роль и (для капитанов) назначение судна автоматически установлены

### Шаг 6: При первом логине
- **Администратор**: видит Dashboard с глобальной статистикой
- **Суперинтендант**: видит FleetDashboard со своим флотом
- **Капитан**: автоматически редиректится на страницу своего судна (`/vessel/:assetId`)

## Технические деталили реализации

### User Entity
```json
{
  "role": "admin" | "superintendent" | "captain",
  "asset_id": "string (только для капитанов)"
}
```

### Хук `useRoleAccess()`
```javascript
const { user, isAdmin, isSuperintendent, isCaptain, assignedAssetId } = useRoleAccess();
```

### Role-Based Navigation
- **Layout** компонент использует хук `useRoleAccess()` для фильтрации меню навигации
- Разные роли видят разные пункты меню:
  - Admin: управление клиентами, судами, пользователями, справочники
  - Superintendent: флот, критические суда, данные анализов
  - Captain: только свое судно

### Role-Based Pages
- **Dashboard** (`/`): показывает разные данные в зависимости от роли
- **FleetDashboard** (`/fleet`): доступна для администратора и суперинтенданта
- **CriticalVessels** (`/critical`): для суперинтенданта и администратора
- **UserManagement** (`/users`): только для администратора

### Фильтрация данных
- Если пользователь - капитан, все запросы данных фильтруются по его `asset_id`
- Dashboard автоматически редирект капитана на его судно

## Сценарии использования

### Сценарий 1: Новый суперинтендант
1. Admin отправляет приглашение супер@mail.com с ролью "Суперинтендант"
2. Супер регистрируется
3. Видит FleetDashboard со всеми судами компании
4. Может переходить в детали каждого судна

### Сценарий 2: Новый капитан судна
1. Admin отправляет приглашение kapitan@mail.com с ролью "Капитан"
2. Admin выбирает из списка судно "Волга-1"
3. Капитан регистрируется
4. При логине автоматически видит только свое судно "Волга-1"
5. Может просматривать оборудование, пробы, рекомендации

## Безопасность

- Row-Level Security (RLS) можно добавить в будущем для дополнительной защиты
- Капитан не может видеть других судов даже если попытается открыть прямую ссылку
- Все данные фильтруются по `asset_id` на уровне запроса

## Управление (для администратора)

- **UserManagement** страница позволяет:
  - Просматривать всех пользователей и их роли
  - Удалять пользователей (если нужно)
  - Видеть, какое судно назначено каждому капитану
