# ADR-0002. Отказ от Base44 в пользу собственного стека

- Статус: принято
- Дата: 2026-08-26
- Заменяет: ADR-0001-C (отдельное приложение Base44), ADR-0001-H в части хранилища
- Не затрагивает: ADR-0001-A, B, D, E, F, G, I, J — слоистая архитектура, двойное
  представление материала, изоляция арендатора, доступ участника по токену, контракт
  агента, недоверенные документы, human-in-the-loop и запрет на уничтожение данных
  остаются в силе без изменений

## 1. Контекст

ADR-0001 выбирал Base44 как основу MVP ради скорости старта. Решение принималось до того,
как стало известно два обстоятельства:

1. У владельца уже есть работающий и обкатанный контур развёртывания: VPS с Docker,
   Caddy с автоматическими сертификатами, деплой через GitHub Actions и `paramiko`,
   секреты в GitHub Secrets, подключённый Anthropic SDK. Главный аргумент за Base44 —
   «зато не нужно заниматься инфраструктурой» — в этих условиях почти ничего не даёт.
2. Платформа продаётся внешним организациям с первого дня. Это переводит изоляцию
   арендаторов, экспорт и удаление данных клиента из «Phase 3» в требования релиза.

Дополнительно при реализации слоя хранения на Base44 обнаружились ограничения, которые
не обходятся без потери качества продукта.

## 2. Решение

Платформа расследований работает на собственном стеке:

| Слой | Выбор |
|---|---|
| Хранилище | PostgreSQL 16 + pgvector, контейнер `pgvector/pgvector:pg16` |
| Изоляция арендаторов | Row-level security PostgreSQL, роль приложения без `bypassrls` |
| API | Node 22 + Fastify, `src/investigation/server` |
| Очередь задач | `investigation_job` в той же базе; отдельный Redis не вводится |
| Файлы | Том на сервере, путь по SHA-256 содержимого |
| Модель | Anthropic SDK на сервере, белый список моделей |
| Обратный прокси | Caddy, автоматический TLS, поддомен `regattayg.space` |
| Развёртывание | GitHub Actions → `paramiko` → Docker на VPS |

Схема БД, перечисления домена и карта таблиц для репозиториев генерируются из одного
источника — `investigation/tools/entity-definitions.mjs`.

## 3. Почему не Base44

| Ограничение | Чем мешает продукту |
|---|---|
| `filter()` — только равенство по полям | Evidence Matrix, попарный поиск противоречий и timeline требуют настоящих запросов. Первая реализация графа дела вытягивала все сущности в память — на реальном деле это не работает |
| Нет векторного поиска | §49 и §55 ТЗ (RAG, поиск похожих дел и claim, паттерны мошенничества) нереализуемы; первая реализация `KnowledgeStore` была честно помечена как `lexical_degraded` |
| Нет транзакций между сущностями | План расследования — это issues, hypotheses, revisions и tasks одной операцией. Обрыв на середине оставлял дело в полусостоянии |
| Нет внешних ключей | Утверждение могло сослаться на несуществующий источник; целостность держалась на аккуратности кода |
| Неизменяемость журнала — правило RLS, а не гарантия | Владелец приложения правит данные в редакторе. Для расследования, которое может обсуждаться в трудовом споре, это подрывает главное обещание продукта |
| Данные в юрисдикции США | Материалы расследований — персональные данные сотрудников. Для российских клиентов это вопрос 152-ФЗ, а не удобства |

## 4. Что даёт PostgreSQL взамен

Проверено на работающей базе (`investigation/db/checks/isolation.sql`, выполняется ролью
приложения без `bypassrls`):

- сотрудник организации А не видит дело организации Б ни списком, ни по прямому
  идентификатору;
- запись в чужую организацию отклоняется политикой;
- соединение без выставленного контекста арендатора не видит ничего — забытый контекст
  приводит к пустому результату, а не к утечке;
- изменение и удаление записи журнала аудита отклоняется триггером базы;
- код утверждения уникален внутри дела;
- висячая ссылка на источник отклоняется внешним ключом.

То же самое на уровне HTTP проверяется `investigation/tools/smoke-api.mjs`.

## 5. Цена решения

Появляется работа, которой при Base44 не было: аутентификация, миграции, отдача файлов,
администрирование организаций. Это осознанная плата, а не недосмотр.

Не появляется работы там, где могло бы: слоистая архитектура ADR-0001-A строилась ровно
под такую замену. Домен, движок, инварианты, агенты и прикладные сервисы перенесены без
изменений — переписан только слой репозиториев. Приёмочный прогон §81 остался зелёным
и до, и после замены; он же теперь выполняется в двух вариантах — на хранилище в памяти
и на настоящей базе.

## 6. Отвергнутые альтернативы

| Альтернатива | Почему отвергнута |
|---|---|
| Остаться на Base44 | Ограничения выше упираются в обещания продукта, а не в удобство разработки |
| Гибрид: Base44 сейчас, переезд позже | Слой репозиториев пришлось бы написать дважды при уже готовой инфраструктуре |
| Managed Postgres у облачного провайдера | Разумно при росте; сейчас добавляет счёт и внешнюю зависимость там, где свой сервер уже работает |
| Отдельный Redis для очереди | Задачи расследования редки и долги. `investigation_job` в той же базе даёт durability без второго хранилища |
| MinIO/S3 для файлов | Оправдано при мультисерверной установке. Пока сервер один, том с адресацией по хэшу проще и надёжнее |
| Neo4j для графа дела | ADR-0001-H остаётся в силе: граф собирается поверх реляционных связей, интерфейс `GraphRepository` сохранён |

## 7. Следствия и новые обязательства

1. **Доступ к серверу.** Сейчас развёртывание идёт под root по паролю из GitHub Secrets.
   Для ботов это терпимо, для платформы с материалами внутренних расследований — нет.
   Нужен отдельный пользователь развёртывания, вход по ключу и запрет парольной
   аутентификации. Зафиксировано как `KI-018`.
2. **Резервные копии.** База становится единственным носителем расследований. Нужен
   регулярный `pg_dump` с проверкой восстановления и отдельное копирование тома
   источников. Зафиксировано как `KI-019`.
3. **Шифрование при хранении.** §60 ТЗ требует encryption at rest. Для тома с
   оригиналами и каталога базы нужно шифрование на уровне диска. Зафиксировано
   как `KI-020`.
4. **Юридический контур.** Продажа внешним клиентам требует договора об обработке
   персональных данных, описанного порядка экспорта и удаления данных клиента.
   Технически `deleteTenantData` и каскады по организации готовы, юридическая часть — нет.
5. **Отдельный репозиторий.** Платформа больше не делит с SmartOil ни стек, ни базу, ни
   развёртывание. Вынос в собственный репозиторий стал бы естественным шагом; сейчас код
   остаётся здесь по решению владельца.
