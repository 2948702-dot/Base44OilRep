# Методология расследования

Документ фиксирует, какие правила система обязана соблюдать независимо от модели, промпта
и настроения следователя. Технические места, где правило реализовано, указаны явно.

## 1. На чём построена система

- PEACE investigative interviewing: свободный рассказ до уточнений, никакого обвинительного
  начала.
- ACFE fraud examination: работа от документа и от денежного следа, а не от впечатления.
- Evidence-based investigation: утверждение существует отдельно от его подтверждения.
- Hypothesis testing: версия ценна тем, чем её можно опровергнуть.
- Corroboration: независимость источников важнее их количества.
- Contradiction analysis: расхождение — это задача, а не приговор.
- Source attribution: у каждого утверждения есть источник и позиция в нём.
- Timeline analysis: конкурирующие версии времени сохраняются.
- Root cause analysis: почему система позволила событию произойти.
- Adversarial review: основную версию проверяет тот, кто её не строил.
- Auditability: любой вывод воспроизводим.

## 2. Чего система не делает

Запрещено строить архитектуру вокруг определения лжи по стилю речи, эмоциям, голосу,
паузам, выражению лица и другим ненадёжным психологическим признакам.

Такие признаки не имеют доказательной силы, зато создают ложную уверенность и переносят
расследование с проверяемых фактов на впечатление о человеке. Ни одна сущность модели
данных не хранит оценку правдивости человека, и ни один агент не вправе её выводить.

Система анализирует цепочку:

```text
утверждения → источники → объективные доказательства → противоречия → подтверждения
→ альтернативные объяснения
```

## 3. Неизменяемые принципы (§71 ТЗ)

| Принцип | Где обеспечен |
|---|---|
| Никогда не уничтожать оригинальные материалы | soft delete в `createEntityRepository`, derived Source в `SourceService` |
| Никогда не переписывать прошлый ответ человека | `InterviewService.correctTranscript` хранит `original_version` |
| Никогда не скрывать противоречащее evidence | `ClaimEvidenceLink.relation = contradicts` не удаляется; Red Team получает полный набор |
| Никогда не заменять источник AI-summary | `Claim.source_id` + `source_locator` обязательны, `assertClaimIsAttributed` |
| Никогда не обозначать человека виновным из-за LLM inference | `subject` только через `ApprovalRequest`, `assertSubjectDesignationApproved` |
| Никогда не выводить «lie probability» | шкала уверенности качественная, `assertQualitativeConfidence` |

## 4. Уверенность

Пять уровней: Very Low, Low, Moderate, High, Very High.

Уверенность относится к:

- подтверждённости утверждения;
- оценке времени события;
- выводу.

Уверенность не относится к честности человека. Числовые и процентные оценки виновности
запрещены: `assertQualitativeConfidence` отклоняет любое значение вне шкалы.

Правило вывода уверенности в подтверждении (`corroborationConfidence`) намеренно
консервативно: несколько зависимых пересказов одного источника не дают высокой уверенности,
а объективное доказательство весит больше согласованных показаний.

## 5. Приблизительность

«Около семи» — интервал `18:30–19:30` с `time_precision = hour`, а не `19:00:00`.
«Примерно 74 тысячи» — сумма 74000 с пометкой приблизительности.

Точность может только понижаться при пересказе и повышаться только при появлении нового
источника. Попытка повысить точность без источника отклоняется
инвариантом `PRECISION_NOT_INFLATED`.

## 6. Человек в контуре

Обязательное утверждение человеком требуется перед:

1. отправкой первого набора интервью;
2. отправкой чувствительного challenge-вопроса;
3. переводом человека в статус `subject`;
4. закрытием гипотезы;
5. утверждением Finding;
6. выпуском итогового отчёта.

Уровни автономии: A0 — только черновики, A1 — предложение действий, A2 — автоматические
рутинные вопросы, A3 — автоматическое расследование. В MVP допустимы A1 и A2;
`CaseService.createCase` отклоняет остальные.

## 7. Цикл дообследования

```text
Round N → Claim Extractor → Timeline → Contradiction Analysis → Hypothesis Review
       → Red Team → Follow-Up Planner → утверждение человеком → Round N+1
```

Остановка возможна по четырём причинам: следователь остановил, вопросы разрешены,
доказательства недоступны, прирост информации пренебрежим. Первые три — решение по существу,
четвёртая проверяется `evaluateFollowUpNeed` и намеренно консервативна: раунд не
прекращается только потому, что предыдущий дал мало нового.

## 8. Метрики качества (§52 ТЗ)

Особо значимы:

- **Unsupported Claim Rate** — доля утверждений отчёта без ссылки на источник. Целевое
  значение — ноль; обеспечивается инвариантами `CLAIM_REQUIRES_SOURCE`
  и `FACT_REQUIRES_EVIDENCE`.
- **False Accusation Rate** — доля дел, где неблагоприятный вывод сделан в отношении
  человека, не причастного по ground truth. Ключевая метрика безопасности.
- **Premature Closure Rate** — доля дел, где альтернативная версия закрыта до получения
  доказательства, способного её проверить. Ограничивается инвариантом
  `ALTERNATIVES_MUST_SURVIVE` и требованием approval на закрытие гипотезы.

Остальные метрики: Fact Recall, Contradiction Detection, Relevant Question Rate,
Evidence Request Quality, Hypothesis Diversity, Alternative Hypothesis Preservation,
Timeline Accuracy, Financial Trace Accuracy, Source Citation Accuracy.

Измеряются на `TrainingCase` с известным ground truth в Phase 3.
