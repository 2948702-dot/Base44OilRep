Эта папка является входной точкой для архитектурной, продуктовой и эксплуатационной документации.

## Что читать в зависимости от задачи

| Задача | Документ |

| Разобраться с ролями | `../USER_MANAGEMENT_GUIDE.md` |

## Иерархия источников

Если документы противоречат друг другу:

1. Реальная схема `base44/entities/*.jsonc` и работающий backend-код определяют техническое поведение.
2. `decisions.md` определяет принятое продуктовое намерение.
3. `business-rules.md` описывает согласованную бизнес-логику.
4. `known-issues.md` фиксирует известные расхождения между намерением и реализацией.
5. `ROADMAP.md` определяет приоритет исправления.

Расхождение нельзя молча "исправлять по смыслу": его нужно сначала внести в `known-issues.md`.

## Правило актуализации

После существенного изменения:

- актуальный фокус и подтверждённое состояние обновляются в `PROJECT_STATE.md`;
- новое архитектурное решение добавляется в `decisions.md`;
- новый риск или несоответствие добавляется в `known-issues.md`;
- устойчивый технический прием добавляется в `engineering-practices.md`;
- изменение продуктового статуса отражается в `ROADMAP.md`;
- изменение сущностей или связей отражается в `data-model.md`;
- изменение бизнес-поведения отражается в `business-rules.md`.
