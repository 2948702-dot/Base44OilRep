# Архитектура SmartOil

## Назначение

SmartOil хранит данные об оборудовании и масле, принимает рабочие и базовые пробы, сохраняет лабораторные измерения, рассчитывает диагностические статусы и связывает их с обслуживанием оборудования.

## Слои

### Frontend

React-приложение в `src/`:

- `src/pages/` - маршруты и пользовательские сценарии;
- `src/components/` - прикладные компоненты и UI;
- `src/hooks/` - авторизация, роли и общие сценарии;
- `src/utils/` - резолверы порогов, базовых проб, payload и отчетов.

Маршруты зарегистрированы в `src/App.jsx`. Доступность пункта меню не является защитой данных: безопасность обязана обеспечиваться RLS и backend-проверками.

### Data layer

Схемы Base44 находятся в `base44/entities/*.jsonc`. Они определяют поля, обязательность и RLS. Для быстрого RLS часть записей хранит денормализованные `client_id` и `asset_id`.

### Backend

Каждая папка в `base44/functions/` - самостоятельная serverless-функция Deno. Функции:

- проверяют пользователя до `asServiceRole`;
- выполняют атомарную прикладную операцию;
- пересчитывают производные snapshot-поля;
- восстанавливают связанные данные после изменения истории.

Локальные shared-импорты между функциями в этом проекте не считаются надежно поддерживаемыми Base44.

## Основные потоки данных

### Проба и анализ

```text
EquipmentUnit
  -> OilSample (контекст и snapshot на момент отбора)
  -> AnalysisResult (лабораторные значения)
  -> threshold resolver
  -> статус параметров, OHI, dashboards и reports
```

### Обслуживание

```text
MaintenanceEvent
  -> пересчет EquipmentUnit.current_*
  -> пересборка OilLifecycle
  -> план-факт MaintenanceSchedule
  -> прогнозы и dashboards
```

### Пороговые правила

```text
EquipmentUnit.use_standard_thresholds = false
  -> EquipmentUnit.custom_thresholds

иначе
  -> ThresholdRule выбранного OilReference
```

Универсальные правила без масла продуктом не используются.

### Базовое свежее масло

Для рабочей пробы система сначала ищет лабораторный анализ свежего масла по приоритету назначения, а при его отсутствии использует доступные паспортные значения масла. Подробный порядок зафиксирован в `business-rules.md`.

## Источники истины

| Область | Источник истины | Производные данные |
|---|---|---|
| Моточасы | `MaintenanceEvent` | `EquipmentUnit.current_total_hours`, `current_oil_hours` |
| Текущее масло | последнее релевантное событие и ручная синхронизация справочника | `EquipmentUnit.current_oil_type_id` |
| Лаборатория | `AnalysisResult` | статусы, OHI, графики |
| Порог | custom агрегата или правило масла | цветовой статус |
| Контекст отбора | `OilSample` | отчеты и история |
| Жизненный цикл масла | хронология `oil_change` | `OilLifecycle` и привязки проб |

## Безопасность

- `admin` работает со всеми клиентами.
- `superintendent` ограничен своим `client_id`.
- `captain` - техническая роль ответственного за один или несколько назначенных активов.
- UI-фильтрация нужна для корректного интерфейса, но не заменяет RLS/backend.
- Любой `asServiceRole` допустим только после проверки области доступа исходного пользователя.

Известное расхождение поддержки `asset_ids` в RLS описано в `known-issues.md`.

## Интеграция и поставка

GitHub является версионируемым источником кода. Base44 синхронизирует основную ветку с редактором приложения. Production-публикация выполняется отдельно в Base44 после приемки.

Живые production-проверки выполняются через Base44-плагин Codex либо через CLI + Deno по `base44-live-access.md`.
