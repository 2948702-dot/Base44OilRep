# Известные проблемы и технический долг

Это реестр подтвержденных рисков. Он не заменяет GitHub Issues, но дает агенту обязательный контекст до изменения системы.

## Активные

| ID | Приоритет | Проблема | Риск | Следующее действие |
|---|---|---|---|---|
| KI-001 | P0 | Не все JSON-RLS проверяют `User.asset_ids`; часть правил сравнивает только `user.asset_id` | Ответственный за несколько активов может не увидеть разрешенные данные либо архитектура начнет полагаться на UI | Спроектировать безопасный backend-контур чтения/записи или согласовать модель одного asset в RLS |
| KI-002 | P0 | Пересборка `OilLifecycle` после desktop/mobile изменения события требует приемки на production-подобных данных | Неверная привязка проб и длительности масла | Прогнать create/update/delete/backdate сценарии и сохранить результаты |
| KI-003 | P0 | План-факт замены масла связан кодом, но не имеет зафиксированного acceptance-набора | Дашборды могут неверно показывать просрочку или факт | Создать таблицу сценариев по датам и моточасам |
| KI-004 | P1 | Руководство и UI поддерживают несколько активов, но безопасность распределена между RLS и backend | Несогласованное поведение страниц и операций | Составить матрицу CRUD по сущностям и ролям |
| KI-005 | P1 | Не все формы проверены на обязательный `buildPayload + useSaveMutation` | Возможны тихие несохранения и отсутствие сообщения об ошибке | Провести отдельный grep-аудит форм и мигрировать оставшиеся |
| KI-006 | P1 | В удаленной БД могут оставаться legacy-записи `SamplingPoint` | Разработчики могут принять их за актуальный источник | После проверки деплоя схемы удалить отдельной admin-операцией |
| KI-007 | P2 | Не определен жизненный цикл ручной корректировки `SamplingSchedule` | Следующая проба может неожиданно перезаписать план | Утвердить вариант в DEC-016 и реализовать серверное правило |
| KI-008 | P2 | `notification_enabled` существует без механизма доставки | UI создает ложное ожидание уведомлений | Выбрать первые сценарии и канал в следующем релизе |
| KI-009 | P2 | Схема `ThresholdRule` содержит legacy scope-поля | Агент может вернуть устаревшую привязку к типу/узлу | Не использовать их без нового решения; позже выполнить миграцию схемы |
| KI-010 | P2 | Дублированный `recalcUnit` в backend-функциях | Исправление одной копии может рассинхронизировать поведение | До доказанного function-to-function обновлять все копии и проверять diff |
| KI-011 | P2 | `npm run typecheck` не проходит на текущем baseline | Ошибки типов скрывают новые регрессии и создают шум при приемке | Отдельно настроить JSX-типы, декларации Base44 SDK и постепенно закрыть существующий список |
| KI-012 | P1 | Для `client_admin` нужна безопасная backend-функция приглашения пользователей франчайзи | Прямой доступ к `User.list/update` может раскрыть лишние учетные записи или дать слишком широкие права | Спроектировать `inviteScopedUser` с проверкой `client_id` и разрешенных ролей |
| KI-013 | P0 | Платформа расследований не развёрнута на сервере: поддомен, секреты и первый прогон Action не выполнены | Код и проверки готовы, но продукта на живых данных пока нет | Направить `investigation.regattayg.space` на сервер, добавить секреты, запустить Action «Deploy investigation platform» |
| KI-015 | P1 | Реализованы 5 агентов из 18; Timeline, Contradiction, Hypothesis Analyst и Report Writer отсутствуют | Полный цикл расследования не замкнут: противоречия и timeline пока не строятся автоматически | Реализовать по `mvp-plan.md`, начиная с Interview Strategist и Timeline Analyst |
| KI-016 | P1 | Векторный поиск технически готов (pgvector, `semanticSearch`), но эмбеддинги не строятся: функция построения вектора не подключена | Поиск похожих дел и claim не работает; `semanticSearch` отказывает явно, чтобы не подменять качество молча | Подключить построение эмбеддингов и наполнить методологическое пространство знаний |
| KI-017 | P1 | Исполнителя очереди `investigation_job` нет: задачи ставятся в очередь, но не выполняются автоматически | Извлечение утверждений и транскрипция запускаются только явным вызовом сервиса | Реализовать исполнителя внутри контейнера API с блокировкой `for update skip locked` |
| KI-018 | P0 | Развёртывание идёт под root по паролю из GitHub Secrets | Компрометация секрета даёт полный контроль над сервером с материалами расследований | Завести пользователя развёртывания, вход по ключу, запретить парольную аутентификацию и вход root по SSH |
| KI-019 | P0 | Резервное копирование базы и тома источников не настроено | База стала единственным носителем расследований; потеря тома означает потерю дел и оригиналов | Настроить регулярный `pg_dump` с проверкой восстановления и копирование тома источников за пределы сервера |
| KI-020 | P1 | Шифрование при хранении, требуемое §60 ТЗ, не включено | Материалы внутренних расследований лежат на диске открыто | Включить шифрование тома с оригиналами и каталога базы |
| KI-021 | P1 | Юридический контур продажи внешним клиентам не готов: нет договора об обработке персональных данных и описанного порядка экспорта | Технически `deleteTenantData` и каскады готовы, продавать без юридической части нельзя | Подготовить договор и регламент экспорта и удаления данных клиента |
| KI-022 | P2 | `RelationalGraphRepository.buildCaseGraph` собирает граф дела в памяти приложения | На деле с тысячами утверждений это станет узким местом | Переписать сборку графа на SQL с рекурсивным обходом; интерфейс `GraphRepository` менять не нужно |

## Недостающие контрольные документы

После этого аудита остаются полезными, но еще не созданными:

- матрица ролей x сущностей x CRUD;
- реестр страниц и доступных ролей;
- формализованный acceptance-набор для maintenance/lifecycle/plan-fact;
- журнал выполненных production-проверок с датой, средой и результатом.

## Закрытие проблемы

При закрытии:

1. добавить ссылку на commit/PR или тестовый отчет;
2. обновить `ROADMAP.md`;
3. при изменении продуктового решения обновить `decisions.md`;
4. не удалять полезный контекст причины и способа проверки.
