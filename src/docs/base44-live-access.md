# Живой доступ к Base44 для проверки данных

Проверенная схема для AI-агентов и разработчиков, которым нужно читать реальные данные приложения, проверять функции и диагностировать production-поведение.

## Два независимых канала

### 1. Base44-плагин Codex

Удобен для запросов к схемам и сущностям прямо из диалога Codex.

Особенность: OAuth-токен приложения и авторизация Base44 CLI не связаны. Успешный `base44 whoami` не обновляет токен плагина.

Если плагин возвращает `token_expired`:

1. Открыть страницу подключений Codex: `https://chatgpt.com/codex/settings/connectors`.
2. Переподключить приложение Base44.
3. Полностью перезапустить Codex.
4. Начать новый поток: уже открытый поток может продолжать использовать старый OAuth-контекст.
5. Проверить подключение простым запросом списка приложений или схем.

Не пытаться создавать бессрочный OAuth-токен. Срок жизни и обновление токена контролирует Base44.

### 2. Base44 CLI + Deno

Это основной резервный канал для живых проверок. Он работает независимо от OAuth-плагина Codex.

Преимущества:

- сессия Base44 хранится локально;
- можно читать сущности, вызывать функции и смотреть production-логи;
- `base44 exec` использует текущего авторизованного пользователя и его права;
- не требуется создавать временную backend-функцию.

## Первичная настройка на Windows

### Проверить привязку проекта

В репозитории должны существовать:

- `base44/config.jsonc`;
- `base44/.app.jsonc` с ID приложения.

ID приложения не является секретом. Токены и пароли в репозиторий не записываются.

### Использовать локальный npm-кэш

Системный npm-кэш Windows может быть недоступен агенту с ошибкой `EPERM`. Поэтому команды CLI запускаются с кэшем внутри рабочего каталога:

```powershell
& 'C:\Program Files\nodejs\npx.cmd' --yes --cache .npm-cache base44 whoami
```

Каталог `.npm-cache/` добавлен в `.gitignore`.

### Авторизоваться

```powershell
& 'C:\Program Files\nodejs\npx.cmd' --yes --cache .npm-cache base44 login
```

CLI покажет код и адрес `https://app.base44.com/login/device`. После подтверждения проверить:

```powershell
& 'C:\Program Files\nodejs\npx.cmd' --yes --cache .npm-cache base44 whoami
```

Ожидаемый результат: `Logged in as: user@example.com`.

### Установить Deno

`base44 exec` требует Deno:

```powershell
winget install --id DenoLand.Deno -e --accept-package-agreements --accept-source-agreements
```

После установки открыть новый терминал и проверить:

```powershell
deno --version
```

## Read-only проверка реальных данных

Перед любым запросом:

1. Проверить `whoami`.
2. Убедиться, что команда запущена из нужного репозитория.
3. Сначала выполнять только чтение.
4. Не использовать `create`, `update`, `delete` без прямого запроса владельца и отдельной проверки области изменений.

Пример контрольного запроса:

```powershell
@'
const [assets, units, samples, results] = await Promise.all([
  base44.entities.Asset.list(),
  base44.entities.EquipmentUnit.list(),
  base44.entities.OilSample.list(),
  base44.entities.AnalysisResult.list(),
]);

console.log(JSON.stringify({
  assets: assets.length,
  equipmentUnits: units.length,
  samples: samples.length,
  analysisResults: results.length,
}));
'@ | & 'C:\Program Files\nodejs\npx.cmd' --yes --cache .npm-cache base44 exec
```

Пример проверки backend-функций:

```powershell
& 'C:\Program Files\nodejs\npx.cmd' --yes --cache .npm-cache base44 functions list
```

На 13 июня 2026 года через CLI успешно прочитаны production-данные:

- 6 активов;
- 7 агрегатов;
- 6 проб;
- 9 результатов анализа;
- 6 развёрнутых backend-функций.

Проверка также подтвердила:

- у всех шести активов есть `AnalysisResult`;
- у этих результатов не рассчитан `oil_health_index`;
- правила диэлектрики содержат вложенные красный, жёлтый и зелёный диапазоны.

Это позволило подтвердить причины двух UI-дефектов не по предположению, а на реальных данных.

## Типичные ошибки

### `EPERM` в системном npm-кэше

Использовать `--cache .npm-cache`.

### `Deno is required to run scripts with exec`

Установить Deno, открыть новый терминал и проверить `deno --version`.

### CLI работает, а плагин возвращает `token_expired`

Это разные авторизации. CLI можно использовать как рабочий канал; плагин переподключается отдельно, после чего нужен новый поток Codex.

### Команда зависла на `Waiting for authentication`

Открыть указанный URL, ввести код из того же окна терминала и дождаться подтверждения. Повторный запуск `whoami` во время незавершённого входа создаст новый код и может запутать процесс.

## Универсальное правило для других проектов

Для каждого Base44-проекта поддерживать оба канала:

1. Плагин Codex для быстрых интерактивных запросов.
2. CLI + Deno как независимый диагностический резерв.

Наличие резервного канала обязательно для приёмки критичных изменений, проверки RLS, production-данных и backend-функций.
