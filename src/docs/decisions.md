# Журнал решений SmartOil

Решения фиксируют продуктовое намерение. При изменении решения старая запись не удаляется: добавляется новая со ссылкой на замененную.

| ID | Статус | Решение | Причина |
|---|---|---|---|
| DEC-001 | принято | Один `EquipmentUnit` является одним местом отбора; `SamplingPoint` не используется | В текущем продукте у агрегата нет нескольких независимых точек |
| DEC-002 | принято | Моточасы и текущее масло выводятся из `MaintenanceEvent` | Нужна воспроизводимая история, корректная правка задним числом и единый источник истины |
| DEC-003 | принято | Стандартные пороги привязаны к маслу, индивидуальные - к агрегату | Тип оборудования не определяет норматив надежнее конкретного масла и состояния узла |
| DEC-004 | принято | Универсальных порогов без масла нет | Любая граница должна иметь конкретный физический контекст |
| DEC-005 | принято | Система не валидирует совместимость масла и типа агрегата | SmartOil диагностирует, но не запрещает технологическое решение клиента |
| DEC-006 | принято | Лабораторная проба свежего масла имеет приоритет над паспортом | Реальная партия масла точнее справочного паспорта |
| DEC-007 | принято | Одна свежая проба может назначаться нескольким агрегатам/lifecycle | Одна бочка часто разливается на несколько узлов |
| DEC-008 | принято | `captain` остается техническим именем роли, должность хранится отдельно | Одна область прав должна работать для капитана, оператора, механика и начальника участка |
| DEC-009 | принято | Ответственный может иметь несколько `asset_ids` | Практический пользователь нередко отвечает за несколько активов |
| DEC-010 | принято | Семь неиспользуемых паспортных полей OilReference скрыты, но не удалены из схемы | Не ломать совместимость данных и не перегружать рабочую форму |
| DEC-011 | принято | Формы отправляют whitelist payload и показывают ошибки сохранения | Base44 может отклонить payload с системными полями, а тихое закрытие формы опасно |
| DEC-012 | принято | Жизненные циклы пересобираются хронологически | Точечное обновление ломается при удалении, переносе и задней дате событий |
| DEC-013 | принято | GitHub хранит версионируемый код, Base44 выполняет синхронизацию и публикацию | Нужны review, история и воспроизводимость изменений |
| DEC-014 | принято | Для живой проверки поддерживаются плагин и CLI+Deno | OAuth-сессии независимы, отказ одного канала не должен блокировать приемку |
| DEC-015 | отложено | Централизация `recalcUnit` через function-to-function | Нужна приемка передачи контекста для всех ролей; до этого надежнее синхронные копии |
| DEC-016 | открыто | Семантика ручного override `SamplingSchedule` после следующей пробы | Нужно выбрать одноразовое, постоянное или автоматически перезаписываемое значение |
| DEC-017 | принято | Франчайзи получает scoped-роли `client_admin` и `lab_technician`; лабораторный ввод доступен только `admin` и `lab_technician` | У каждого покупателя оборудования будет свой админ и лаборант, но их права не должны совпадать с глобальным админом SmartOil |

## Как добавлять решение

Новая запись должна отвечать на четыре вопроса:

1. Что решено?
2. Почему?
3. Какие файлы и данные затрагивает?
4. Как отменить или заменить решение?

Если реализация еще не соответствует принятому решению, добавить отдельный пункт в `known-issues.md`.
