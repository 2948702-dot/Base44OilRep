# Журнал решений SmartOil

Решения фиксируют продуктовое намерение. При изменении решения старая запись не удаляется: добавляется новая со ссылкой на замененную.

| ID | Статус | Решение | Причина |
|---|---|---|---|
| DEC-001 | принято | Один `EquipmentUnit` является одним местом отбора; `SamplingPoint` не используется | В текущем продукте у агрегата нет нескольких независимых точек |
| DEC-002 | принято | Моточасы и текущее масло выводятся из `MaintenanceEvent` | Нужна воспроизводимая история, корректная правка задним числом и единый источник истины |
| DEC-003 | принято | Стандартные пороги привязаны к маслу, индивидуальные - к агрегату | Тип оборудования не определяет норматив надежнее конкретного масла и состояния узла |
| DEC-004 | принято | Универсальных порогов без масла нет | Любая граница должна иметь конкретный физический контекст |
| DEC-005 | принято | Система не валидирует совместимость масла и типа агрегата | SmartOil диагностирует, но не запрещает технологическое решение клиента |
| DEC-006 | принято | Лабораторная проба свежего масла имеет приоритет над паспортом | Реальная партия масла точнее справочного паспорта |
| DEC-007 | принято | Одна свежая проба может назначаться нескольким агрегатам/lifecycle | Одна бочка часто разливается на несколько узлов |
| DEC-008 | принято | `captain` остается техническим именем роли, должность хранится отдельно | Одна область прав должна работать для капитана, оператора, механика и начальника участка |
| DEC-009 | принято | Ответственный может иметь несколько `asset_ids` | Практический пользователь нередко отвечает за несколько активов |
| DEC-010 | принято | Семь неиспользуемых паспортных полей OilReference скрыты, но не удалены из схемы | Не ломать совместимость данных и не перегружать рабочую форму |
| DEC-011 | принято | Формы отправляют whitelist payload и показывают ошибки сохранения | Base44 может отклонить payload с системными полями, а тихое закрытие формы опасно |
| DEC-012 | принято | Жизненные циклы пересобираются хронологически | Точечное обновление ломается при удалении, переносе и задней дате событий |
| DEC-013 | принято | GitHub хранит версионируемый код, Base44 выполняет синхронизацию и публикацию | Нужны review, история и воспроизводимость изменений |
| DEC-014 | принято | Для живой проверки поддерживаются плагин и CLI+Deno | OAuth-сессии независимы, отказ одного канала не должен блокировать приемку |
| DEC-015 | отложено | Централизация `recalcUnit` через function-to-function | Нужна приемка передачи контекста для всех ролей; до этого надежнее синхронные копии |
| DEC-016 | открыто | Семантика ручного override `SamplingSchedule` после следующей пробы | Нужно выбрать одноразовое, постоянное или автоматически перезаписываемое значение |
| DEC-017 | принято | Франчайзи получает scoped-роли `client_admin` и `lab_technician`; `client_admin` включает права лаборанта и мобильного оператора в своей области | На старте покупатель франшизы может работать один: отбирать пробу, анализировать и вводить результаты, но его права не должны совпадать с глобальным админом SmartOil |
| DEC-018 | заменено DEC-024 | Платформа AI Investigation разрабатывается в этом репозитории как отдельный продукт со своим каталогом схем Base44 | Слияние сущностей расследования в приложение SmartOil изменило бы его схему и RLS без разрешения владельца |
| DEC-019 | принято | Архитектура расследования слоистая: UI → Services → Engine → Agents → Repositories → Base44 | Base44 выбран за скорость старта MVP; замена хранилища не должна переписывать методологию |
| DEC-020 | принято | Схемы Base44 и перечисления домена генерируются из одного определения | Ручная синхронизация RLS 28 сущностей расходится незаметно и создаёт дыру в изоляции tenant |
| DEC-021 | принято | Методологические правила выражаются инвариантами в коде, а не только текстом промпта | Модель может нарушить правило, а следователь под давлением сроков не заметить |
| DEC-022 | частично заменено DEC-024 | Neo4j и Redis не подключаются; вводятся интерфейсы `GraphRepository`, `KnowledgeStore`, `Job` | Потребность не доказана; абстракция стоит дёшево, преждевременная инфраструктура дорого. Отказ от Postgres отменён |
| DEC-023 | принято | `AgentRun` пишется один раз по завершении запуска; состояние незавершённого выполнения живёт в `InvestigationJob` | Журнал запусков должен быть неизменяемым, иначе воспроизводимость Finding не гарантируется |
| DEC-024 | принято | Платформа расследований работает на собственном стеке: PostgreSQL 16 + pgvector, Node 22 + Fastify, Docker на VPS владельца, Caddy, деплой через GitHub Actions | Base44 не даёт полноценных запросов, векторного поиска, транзакций, внешних ключей и гарантии неизменяемости журнала; инфраструктура владельца уже обкатана, а продажа внешним клиентам делает изоляцию и место хранения данных требованием релиза |
| DEC-025 | принято | Изоляция арендаторов обеспечивается row-level security PostgreSQL; роль приложения создаётся без `bypassrls` | Изоляция не должна зависеть от корректности прикладного кода: забытый фильтр обязан давать пустой результат, а не утечку |
| DEC-026 | принято | Журнал аудита, запуски агентов и история статусов гипотез защищены триггером базы от изменения и удаления | Обещание воспроизводимости расследования не может держаться на соглашении приложения |
| DEC-027 | принято | Приёмка методологии выполняется в двух вариантах: на хранилище в памяти и против настоящей базы | Расхождение поведения драйверов означало бы, что приёмка проверяет не то, что работает на сервере |
| DEC-028 | принято | Граница дела внутри организации проверяется в слое хранения, а не в маршрутах: `get` не возвращает объект чужого дела, `update` не проставляет `case_id` | RLS базы разделяет только организации. Проверка «объект принадлежит делу» в каждом из двадцати обработчиков теряется в одном из них, и этого достаточно |
| DEC-029 | принято | Вопрос интервью становится виден участнику только вместе с выдачей ссылки, а чувствительный — отдельным решением человека с обоснованием | Утверждение отправки раунда и есть решение человека о составе вопросов; отдельного решения требует лишь то, что раскрывает участнику ход расследования |
| DEC-030 | принято | Разделение обязанностей (решение принимает не тот, кто запросил) включается настройкой развёртывания `REQUIRE_SEPARATE_APPROVER` | В организации из одного следователя жёсткое требование остановило бы работу; там, где это требование регламента, оно должно действовать в коде |
| DEC-031 | принято | Недоверенный материал обезвреживается по границам блока и помечается случайной меткой запуска | Обещание «инструкции только в секции INSTRUCTIONS» должно описывать структуру промпта, а не намерение |
| DEC-032 | принято | Нераспознанный двоичный формат отклоняется с объяснением, а не разбирается как текст | Молчаливый разбор мусора даёт утверждения, которых в документе нет, и следователь видит «разбор выполнен» |
| DEC-033 | принято | Симулятор прогоняет учебное дело теми же агентами и сервисами, что и настоящее расследование; отдельного «агента-следователя» нет | Измерять имеет смысл только то, что поставляется; тренировочный следователь измерял бы сам себя |
| DEC-034 | принято | Скрытая истина учебного дела сравнивается с материалами дела по спискам маркеров, а не по смысловой близости | Оценка обязана быть воспроизводимой; «примерно совпало» не показывает ни полноты, ни пропуска |
| DEC-035 | принято | Защитные метрики (утверждение без опоры, ложное обвинение, преждевременное закрытие, исключение верной версии) решают исход прогона сами по себе | Расследование, нашедшее почти все факты и назвавшее непричастного, не является хорошим расследованием |
| DEC-036 | принято | В прогоне симулятора утверждения человека проставляются автоматически | Это намеренно худший случай: измеряется, что пройдёт в отчёт, если следователь подпишет всё предложенное |
| DEC-037 | принято | Отчёт по учебному делу не выпускается (`TRAINING_CASE_REPORT_CANNOT_BE_RELEASED`) | Документ, неотличимый по форме от настоящего, обязан быть отличим по статусу |
| DEC-038 | принято | Итоговый отчёт выгружается в DOCX, собираемый на сервере без внешних библиотек; PDF не делается | PDF потребовал бы встраивать шрифт с кириллицей — мегабайты в репозитории и отдельный источник ошибок начертания. DOCX открывается везде, текст остаётся текстом, печать в PDF доступна в любом редакторе |
| DEC-039 | принято | Каждая выгрузка отчёта записывается в журнал аудита операцией `export` | Вынос материалов расследования за пределы системы — событие, а не техническая операция |

## Как добавлять решение

Новая запись должна отвечать на четыре вопроса:

1. Что решено?
2. Почему?
3. Какие файлы и данные затрагивает?
4. Как отменить или заменить решение?

Если реализация еще не соответствует принятому решению, добавить отдельный пункт в `known-issues.md`.
